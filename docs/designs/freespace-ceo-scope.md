## Accepted Scope (added to this plan)
- `diff [/path] [--depth N] [--kind dir|file|any] [--limit N] --json`: current snapshot ATTACHes `snapshot.prev.db` (both opened `immutable=1`), join on stored `path_hash`, rows sorted by `|delta|` of allocated descending (positive first on ties), default `--kind dir --depth 1` (direct children, no parent/child double counting), removed entries always included with negative delta; fields `path, kind, allocated, allocated_prev, delta, items, items_prev`; response carries `prev_generation`, `prev_scanned_at`, `partial` (true when `refresh` ran after prev). Only one previous generation; no `--since`.
- Previous generation kept as `snapshot.prev.db` by hardlink rotation on full `scan` only (`refresh` never rotates prev); older ones deleted; precheck `free ≥ N × size(current) + 512 MB`, N=3 with `keep_previous = true`, N=2 otherwise, first scan uses `100 B × inode count` estimate; `diff` exits 3 with `no previous generation` when absent, 4 on rotation race, 5 on schema mismatch.
- Config file `/etc/freespace/config.toml` with keys `roots, snapshot_dir, keep_previous, workers, port, interval, at` (all but `keep_previous` trace to ARCH-1 hook 3 "configurable paths and port"; `keep_previous` to D6).
- Mutable state moved out of the immutable snapshot into `snapshot_dir/state.json` (`last_error`, `last_success_ts`, `refreshed[]`, `prev_generation`, `current_generation`), written atomically under the scan lock; `roots` table with statvfs `fs_used/fs_total` per generation.
- Publish protocol: hardlink rotation, directory `fsync`, `scan` stores `prev_generation` in the new snapshot's `meta`; `diff` opens current first, then prev, and requires `prev.generation == current.meta.prev_generation` (equality with current = no previous generation, exit 3; other mismatch = rotated, exit 4) — corrected in CEO review Section 4; exit codes: 2 usage, 3 no prev, 4 rotated, 5 schema mismatch, 6 lock held, 7 path-hash collision.
- `refresh` uses the same precheck with N=2 and keeps hardlink attribution for links crossing the subtree boundary; `refresh` itself stays conditional on the benchmark (Open Question 5).
- Latency targets until the benchmark replaces them: `ls`/`top`/`diff` ≤ 300 ms warm, ≤ 2 s cold; `status` ≤ 50 ms.
- `top --older-than <Nd|Nw|Nmo>` (files only, implies `--kind file`) and `--sort mtime|allocated|apparent` on `ls`/`top` (mtime ascending); `mtime` index in schema; web `modified` column sortable and a "Δ since prev" column toggle served by `/api/diff`.
- HTTP API routes enumerated: `/api/status`, `/api/ls`, `/api/top`, `/api/diff`, parameters identical to CLI.
- Hardlink attribution deterministic per snapshot (size to the lexicographically smallest path); `hardlinks(dev, ino, entry_id)` table for `nlink > 1` so `refresh` can keep attribution for links crossing the subtree boundary (fallback: smallest remaining path).
- Schema: DFS-preorder ids with `subtree_end` and `min_scanned_at` so subtree queries (`top /path --older-than`, `age_seconds`) are one index range; `roots_changed` = difference of `roots` tables; exit 1 generic error, exit 8 no snapshot yet.
- SKILL.md orders the agent's standard questions: `diff` → `top --older-than` → `ls`.
- Removed from v1 contract: `--apparent-only`; `tui` subcommand (v1.1).
