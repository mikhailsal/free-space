# Cleanup-threshold prototype: product integration audit

The prototype is a standalone research example, not a product backend. Its potential benefit is to persist far fewer named rows when most entries are below threshold, including small directories; it folds them into per-parent `rest` aggregates without first staging every ordinary entry in SQLite ([walker](https://github.com/mikhailsal/free-space/blob/f7decf817b5bf769c25956713dacc4c4a1870f50/cli/examples/cleanup_probe/walk.rs#L174)). That could reduce retained snapshot/index work, but it still walks and stats every visited entry twice and uses a hardlink-owner map ([scanner](https://github.com/mikhailsal/free-space/blob/f7decf817b5bf769c25956713dacc4c4a1870f50/cli/examples/cleanup_probe/walk.rs#L229)). Actual end-to-end RAM, disk and time gains and behavior on diverse trees require the authorized hosted measurements; row reduction alone does not establish them. Existing CLI, HTTP, security and UI infrastructure can be reused, while scan representation, query semantics and the retained-state update boundary need deliberate work.

This is a source-level impact assessment, not a formal review or an implementation estimate. Source default is v1, while the application can be configured for v2 ([config](https://github.com/mikhailsal/free-space/blob/f7decf817b5bf769c25956713dacc4c4a1870f50/core/src/config.rs#L14)); this audit does not inspect the installed binary or its data.

1. **Essential — choose a product boundary and explicit contract.** Either add an opt-in coarse backend/mode alongside v1/v2, or change v2 under a new, explicitly versioned representation; do not silently reinterpret existing `generations.db`. Backend selection and snapshot paths currently dispatch in [cli/src/backend.rs](https://github.com/mikhailsal/free-space/blob/f7decf817b5bf769c25956713dacc4c4a1870f50/cli/src/backend.rs#L20), and v2 has its own schema and generation model ([v2 schema](https://github.com/mikhailsal/free-space/blob/f7decf817b5bf769c25956713dacc4c4a1870f50/core/src/snapshot/v2/schema.rs#L1)). Decide threshold configuration, filesystem capacity source, budget/cap failure, counts, units, scope and compatibility. An opt-in mode limits regression reach; preserving every existing fine-grained behavior would require additional retained information or a separate representation.

2. **Essential — integrate a coarse walker and error/mount semantics, without fine-grained staging.** The current v2 low-memory seed consumes `StagedTree` and feeds `disk::Sink` ([seed](https://github.com/mikhailsal/free-space/blob/f7decf817b5bf769c25956713dacc4c4a1870f50/core/src/snapshot/v2/seed.rs#L95)); merely filtering after that stage still creates per-entry staging work. The prototype's streaming fold can inform a new core scanner/sink, but currently it aborts on nested mounts, errors, >10 million visits per pass, depth >256, or >100,000 retained/link-owner records ([example walk](https://github.com/mikhailsal/free-space/blob/f7decf817b5bf769c25956713dacc4c4a1870f50/cli/examples/cleanup_probe/walk.rs#L50)). Existing product records mount placeholders and scan incompleteness rather than simply aborting ([staged walker](https://github.com/mikhailsal/free-space/blob/f7decf817b5bf769c25956713dacc4c4a1870f50/core/src/scan/staged/walk.rs#L129), [header](https://github.com/mikhailsal/free-space/blob/f7decf817b5bf769c25956713dacc4c4a1870f50/core/src/queries/types.rs#L12)). Decide whether coarse mode must support the same partial-result and mount contracts; otherwise surface explicit unsupported/failure states. Integrate cancellation, progress, reserve checks, worker limits and `ScanReport` rather than presenting an example-only JSON response as production status ([scan dispatch](https://github.com/mikhailsal/free-space/blob/f7decf817b5bf769c25956713dacc4c4a1870f50/cli/src/backend.rs#L149)). A 100,000-row cap fails the entire run; it is not adaptive budget pruning, and a long chain can exceed it.

3. **Essential — handle roots, filesystem boundaries, and snapshot self-exclusion.** Current product supports multiple roots, filesystem-aware roots and mount/cross-mount policy ([configuration](https://github.com/mikhailsal/free-space/blob/f7decf817b5bf769c25956713dacc4c4a1870f50/core/src/config.rs#L21), [scan arguments](https://github.com/mikhailsal/free-space/blob/f7decf817b5bf769c25956713dacc4c4a1870f50/cli/src/scan.rs#L57)). The example has one canonical root and rejects a snapshot directory under it ([prepare](https://github.com/mikhailsal/free-space/blob/f7decf817b5bf769c25956713dacc4c4a1870f50/cli/examples/cleanup_probe/main.rs#L62)); consequently a normal scan of `/` with its snapshot stored somewhere under `/` is rejected. Product integration needs an identity-safe exclusion for its own database, temporary files, previous generations and sidecars, as well as per-filesystem thresholds, root/mount overlap semantics, bind mounts and threshold persistence across refresh. Do not confuse pathname-prefix checks with filesystem identity, and do not silently omit other real data.

4. **Essential — preserve raw paths, link accounting, and exact aggregate invariants.** Product JSON has `path_raw` to round-trip non-UTF-8 paths ([types](https://github.com/mikhailsal/free-space/blob/f7decf817b5bf769c25956713dacc4c4a1870f50/core/src/queries/types.rs#L31)); the example stores raw BLOB paths and exposes hex in `inspect`, but prints lossy root/boundary text in scan/refresh output. Production adapters need byte-safe paths end to end and a distinct anonymous bucket type, not a fabricated pathname. Existing v2 uses `(dev,ino)` groups and handles outside-subtree owners during refresh ([hardlinks](https://github.com/mikhailsal/free-space/blob/f7decf817b5bf769c25956713dacc4c4a1870f50/core/src/snapshot/v2/hardlinks.rs#L38)); the example conservatively rescans the full root if hardlinks are found ([refresh](https://github.com/mikhailsal/free-space/blob/f7decf817b5bf769c25956713dacc4c4a1870f50/cli/examples/cleanup_probe/main.rs#L283)). Define and test cross-root hardlinks, aliases outside scope, incomplete link sets, ownership changes, sparse files, and `own + retained direct children + rest = total` for sizes, counts, errors and time extrema. The fingerprint comparison detects some observed between-pass changes, not an atomic view of an actively changing filesystem.

5. **Essential — redesign `ls`/top/find/diff responses around information actually retained.** Existing session and API dispatch expects the same fine-grained `LsResponse`, `TopResponse`, `FindResponse` and `DiffResponse` across backends ([dispatch](https://github.com/mikhailsal/free-space/blob/f7decf817b5bf769c25956713dacc4c4a1870f50/cli/src/backend.rs#L47), [HTTP handlers](https://github.com/mikhailsal/free-space/blob/f7decf817b5bf769c25956713dacc4c4a1870f50/cli/src/serve/api.rs#L240)). `ls` assumes named child entries with a true child count; find/top accept per-file name, mtime and allocated-size predicates and return matching counts; diff reports named per-path changes ([response types](https://github.com/mikhailsal/free-space/blob/f7decf817b5bf769c25956713dacc4c4a1870f50/core/src/queries/types.rs#L83), [find](https://github.com/mikhailsal/free-space/blob/f7decf817b5bf769c25956713dacc4c4a1870f50/core/src/queries/find.rs#L25), [diff](https://github.com/mikhailsal/free-space/blob/f7decf817b5bf769c25956713dacc4c4a1870f50/core/src/queries/types.rs#L189)). An anonymous `rest` total cannot answer those queries exactly. Introduce explicit coarse/bucket and coverage semantics or reject unsupported queries; never claim that omitted paths do not exist or that coarse matches are complete. Existing v2 path resolver currently labels absent entries as not in the snapshot ([resolve](https://github.com/mikhailsal/free-space/blob/f7decf817b5bf769c25956713dacc4c4a1870f50/core/src/queries/v2/common.rs#L27)), which would be misleading for intentionally omitted paths. Preserve exact unfiltered parent totals separately from any partial filtered results.

6. **Essential for promised drill-down — add safe, scoped live refinement.** The example's `inspect --path` requires a live `canonicalize` and only chooses an already retained ancestor ([inspect](https://github.com/mikhailsal/free-space/blob/f7decf817b5bf769c25956713dacc4c4a1870f50/cli/examples/cleanup_probe/main.rs#L204)); it does not return the names hidden inside a bucket. A product endpoint/CLI action needs to enumerate the requested live parent or subtree, bound and cancel work, respect permissions and raw paths, and label fresh observation time and errors. It must not silently mutate the baseline or present live results as historical facts. Decide whether refinement is transient or publishes a new generation, what happens if the filesystem changes, and whether filtered search triggers a scan, returns partial coverage or is unavailable.

7. **Essential — redesign refresh, previous-baseline and publication as a coherent transaction.** The example chooses a retained ancestor and can fall back to a whole-root rescan; it rewrites coarse state rather than proving the same incremental behavior as v2. V2 currently validates base generation, updates changed rows, outside hardlink owners and ancestors, and publishes in a SQLite transaction ([writer](https://github.com/mikhailsal/free-space/blob/f7decf817b5bf769c25956713dacc4c4a1870f50/core/src/snapshot/v2/writer.rs#L96)). Existing CLI describes refresh as preserving the previous full-scan baseline ([refresh](https://github.com/mikhailsal/free-space/blob/f7decf817b5bf769c25956713dacc4c4a1870f50/cli/src/refresh.rs#L1)); the example copies its immediately preceding current file to `coarse.prev.db` on every publication ([publish](https://github.com/mikhailsal/free-space/blob/f7decf817b5bf769c25956713dacc4c4a1870f50/cli/examples/cleanup_probe/store.rs#L138)). That difference would change `diff` meaning after refresh. Its two file renames are individually atomic and fsynced but not an atomic current/previous pair under crash. Reuse v2 transactions, reader pinning/retention where appropriate, or design an equivalent atomic generation manifest and recovery protocol; test interrupted writes, concurrent readers/writers, `keep_previous`, threshold changes, root changes, and mixed-age refreshes. Legacy fine-grained history cannot be reconstructed from coarse buckets.

8. **Essential — expose representation and uncertainty in CLI, API and UI; optional polish can follow.** Today web types mirror CLI JSON ([web types](https://github.com/mikhailsal/free-space/blob/f7decf817b5bf769c25956713dacc4c4a1870f50/web/src/types.ts#L1)), rows assume a real path/name/kind and linkable entry ([rows](https://github.com/mikhailsal/free-space/blob/f7decf817b5bf769c25956713dacc4c4a1870f50/web/src/rows.ts#L35)), and status renders incompleteness from `unknown_subtrees` ([notices](https://github.com/mikhailsal/free-space/blob/f7decf817b5bf769c25956713dacc4c4a1870f50/web/src/page-notices.ts#L42)). A useful coarse mode needs a visibly distinct, non-deletable “other” bucket with attributed bytes and counts, a clear expansion action, and separate indicators for intentional coarsening, scan errors and freshness. Update Rust/JSON schemas, TypeScript, CLI text and API consistently; preserve truthful `truncated` and filtered-count semantics. Reuse the existing server/token guards and routes ([server](https://github.com/mikhailsal/free-space/blob/f7decf817b5bf769c25956713dacc4c4a1870f50/cli/src/serve/mod.rs#L71), [router](https://github.com/mikhailsal/free-space/blob/f7decf817b5bf769c25956713dacc4c4a1870f50/cli/src/serve/api.rs#L138)); richer ranking, charts and per-directory threshold controls are optional once core semantics work.

9. **Essential — integrate lifecycle and prove behavior before defaulting on.** Installation, configuration, scheduled scans, snapshot permissions, status, doctor, cleanup/uninstall, and migration/rollback all assume known backend paths ([installer](https://github.com/mikhailsal/free-space/blob/f7decf817b5bf769c25956713dacc4c4a1870f50/cli/src/install.rs#L1), [backend lifecycle](https://github.com/mikhailsal/free-space/blob/f7decf817b5bf769c25956713dacc4c4a1870f50/cli/src/install/lifecycle.rs#L28), [state/status](https://github.com/mikhailsal/free-space/blob/f7decf817b5bf769c25956713dacc4c4a1870f50/cli/src/backend.rs#L85)). Add explicit backend-aware lifecycle handling without deleting or overwriting existing v1/v2 data. Test CLI/API/UI contracts and generation continuity against fine-grained baselines, including non-UTF-8 names, nested roots, mount/denied paths, hardlinks crossing refresh boundaries, invalid capacities, threshold crossings, inode-heavy/long-chain trees, disk exhaustion, crashes and record caps. Measure representative scans and both retained-subtree and omitted-subtree refreshes; an omitted target may select the root and do full work, and hardlinks may also force it. Optional historical per-file diff and exact glob/old-file search remain separate product choices: they cannot be supplied by aggregate-only old snapshots without retaining more data.
