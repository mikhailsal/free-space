Each arm has 15 samples and zero missed ticks. The first and second arms each recorded one late tick, with maximum lateness 20.579836 ms and 20.239417 ms respectively; the third had no late tick and a maximum lateness of 19.256198 ms. The declared tolerance is 20 ms. The frozen validator accepts consistent late counters while requiring zero missed ticks, so the calibration pass includes this lateness. The trace reads individual cgroup files sequentially, so values in a row are not atomic. `slab_reclaimable` is included in `kernel`; other fields also overlap and must not be added. The kernel peak's time is unknown: even a zero numerical gap does not establish that the `memory.stat` values describe the instant of the peak. The sample start times are approximately 65 seconds after CLI start; no live phase markers support phase attribution.

At these samples, each arm reports `pgscan=0`, `pgsteal=0` and `workingset_refault_file=0`; memory PSI some/full totals are zero. Memory PSI, I/O PSI, `io.stat`, and both local and hierarchical memory events were present in all three samples. Their exact raw values and the complete time series are preserved in the archive; zero sampled values do not imply no activity outside the stated interval or remove the non-atomic-read limitation.

The independent calibration evaluations report all eight preregistered overhead bars passed. That finding applies to this same-binary off/on 1m/4 GiB screen only; it does not automatically establish instrumentation overhead at 7.3m entries or lower caps. It is not a product comparison or evidence of memory savings. Runner usage reported at this point is 45,348 seconds (12h 35m 48s) of the 60-hour cap; the campaign ledger remains authoritative. The separate 7.3m-entry baseline completed at 1 GiB under pressure; that is capacity evidence, not a code gain or minimum.

The loop-device receipt reports direct backing-file I/O enabled; this does not isolate the ext4 file cache or kernel metadata charges. A bounded next mechanism investigation could compare fixture shapes at matched entry and payload counts, with the same source, cap, sampler, cold-cache protocol and semantic checks, after prospective admission. Such a control can test whether metadata workload tracks reclaimable slab, but still cannot by itself name a slab object. Separately, a 4 MiB SQLite-cache arm might help the process-RSS guard and could affect cgroup working-set churn; its two 4 MiB nominal target reductions are small relative to the observed slab and do not prove a meaningful total-RAM improvement. Preserve the v1-only scope and the unmeasured v2 effect. Changing to physical storage or changing the sampler requires newly preregistered controls and cannot be folded into this result.
